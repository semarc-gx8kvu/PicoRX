Compile Notes.
==============

You may use pre-compiled firmware for your version of Pico: Pico, Pico2 or Pico2 using RISCV cores. Just copy the UF2 file
onto your Pico (in Boot mode) via USB. Press the white button held before powering up to enable Boot mode.

Conversely, one may wish to make some changes and go 'off piste' in which case read the rest of this section.

I cloned the github rep into a directory PicoRX

Note that the Pico-SDK must be version 2.1.0 as 2.1.1 and 2.1.2 don't work according allegedly.

Import the code by letting VS Code know the location and it will do the rest automatically, almost!

The VS Code Compile button gives this error:

ninja: Entering directory `/home/al/PicoRX/build'
ninja: error: loading 'build.ninja': No such file or directory

AI told me this:

The build system hasn't been configured yet. 
You need to generate the build files first using CMake.

Run this in your terminal:

cd PicoRX
cmake -B build

Then you can build with VS Code 'compile' button.

The LPF or BPF limits can be changed in a menu with a proviso that limits need to be monotonic, 
therefore it should be easy to change them to suit Amateur Bands band-pass filters. 
Conversely it should be fairly simple to hard-code the 3 GPIO pins to match each band's lower and 
upper limits and select position 8 (or 1) for general coverage as a straight through unfiltered link.


Hardware Design Notes:
======================

The Kicad design that can be downloaded, is excellent.  The PCB has a ground plane of almost solid copper
and that will give low noise and the low inductance enables higher frequency performance. Many vias are used
in a matrix pattern to connect to any 0V traces on the top copper layer.

For the Experimenter's Version, I would recommend some changes to the original design:

1. Move the Low-Pass filters away onto another board. The existing PCB uses small s/m capacitors and inductors and they
are almost impossible to alter. The designer admits that BCI (Broadcast Interference) is a problem and states that
band-pass filters would be better. My schematics show both BPF and original LPF circuitry, so that experimenters can
do LT-Spice simulation and change values if required. I am not convinced that the values generated by the
filter design tool will actually work. For the main PCB, these filters would be ignored along with the preamp.
The PCB needs a suitable connector for three filter select signals, power (0V, 3V3 and 5V) and RF into the MUX. 

2. The designer has added support for an Si5351 oscillator module. He mentioned that they need to come from a
reputable supplier. It would be useful to add holes to take an optional module.

3. The designer has also added some Pico pins for future use as a transmitter, but admits that some pins may
need to move.

4. The dual op-amp could be an MCP6022 or equivalent. I used an MCP602, because I had one in the loft, but it is a
fair bit noisier. It's not worth spending a fortune on the device as long as it has low noise, 3 or 5V single supply
and 10MHz or more Gain Bandwidth. 

5. Some versions of the multiplexer (MUX) IC are obsolete, but not all! Some may work on 5V supply only, others 3V only. I have
added a link so the MUX and op-amp can run off either voltage. The bias voltage going into the MUX along with any RF
is set to half the supply. To ensure the Pico is not destroyed by an excessive ADC voltage I have added a single 10.7k resistor
to 0V on each ADC input, but fit only for the 5V MUX. The original design had two resistors on each channel but that is excessive!

6. Some OLED displays have their power pins swapped over so beware! (Been there!) There could be some links on the PCB or the OLED could
be connected to the PCB by 4 wires. The Experimenter's Version is likely to be much larger than the exisiting PCB so
connecting the displays, switches and encoder externally makes sense. I have some 0.96inch OLEDs and 1.2inch and both work 
as they have the same driver chip, same pixel count but the larger ones look much better.

7. MUX chips seem to be s/m only but a SOIC device can be hand-soldered as I have proved, though it did take a couple of goes.



Operating Notes.
================

If the encoder push button is pressed and
the menu button is held then rotating the encoder will change the channel.mode, (CW, AM, AMS(sync AM), LSB, USB, FM) or
if the back button is held then rotating the encoder will change the squelch level, or
otherwise the volume will change.

Very fast tuning is achieved by holding both menu and back buttons. 1kHz steps in CW mode. 100kHz in AM, 10kHz in SSB.
Fast tuning is achieved by holding the menu button. 100Hz steps in CW mode. 10kHz in AM, 1kHz in SSB.
Slow tuning is achieved by holding the back button. 1Hz steps in CW mode. 100Hz in AM, 10Hz in SSB.
